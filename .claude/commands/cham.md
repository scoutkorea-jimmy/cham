# cham — 백로그를 끝까지 민다

$ARGUMENTS

## 규칙

**멈추지 않는다.** 한 항목을 끝내면 **묻지 말고** 다음 항목으로 간다.
"다음으로 갈까요?" 라고 되묻지 않는다 — 이 명령이 그 답이다.
인자로 `한 건만` 이 들어왔으면 한 항목만 끝내고 보고한다.

**사람만 할 수 있는 것은 건드리지 않는다.** `docs/handoff.md` 의 **보류(B\*)** 는
운영자의 결정·값·외부 계정이 필요한 것이다 — 비밀번호 교체, 서치콘솔 등록,
도메인 리다이렉트 방식 선택. 손대지 말고 **보고에만 남긴다.**

## 한 항목의 절차

1. **읽는다** — `docs/handoff.md` 의 '대기' 표에서 **위험도가 가장 높은 것** 하나.
   위험도는 *개인정보·돈·기존 자료 손실*에 가까울수록 높다.
2. **현재 코드를 확인한다** — `CLAUDE.md` 절대규칙 1. 이전 이해가 유효하다고 가정하지 않는다.
   같은 역할의 기존 구현을 먼저 찾는다(규칙 4).
3. **막히면 멈추고 묻는다** — `CLAUDE.md` '멈추고 물어봐야 하는 때'.
   타인의 변경과 충돌 · 데이터 손실 가능 · 인증/인가 동작 변경 · 공개 API 계약 파손.
   막연히 묻지 말고 **구체적인 충돌과 선택지**를 낸다.
4. **만든다** — 규칙집(`rules/`)을 따른다. 토큰만 쓰고, 인라인 `margin` 을 넣지 않는다.
5. **검증한다** — 아래 '검증' 절.
6. **커밋하고 push 한다** — 묻지 않는다(절대규칙 12). 한 관심사에 한 커밋.
7. **배포를 확인한다** — 아래 '배포 확인' 절. **여기서 끝내지 않는다.**
8. **운영에서 실제로 눌러 본다.** 코드를 쓴 것은 완료가 아니다.
9. **기록한다** — `docs/handoff.md` 의 그 줄을 '완료'로 옮긴다.
   되돌리거나 다시 만든 것이 있으면 `docs/failures.md` 에 다섯 칸을 채운다
   (`rules/failure-log.md`). **없으면 억지로 만들지 않는다.**
10. 다음 항목으로 간다.

## 배포 확인 — 옛 코드를 시험하지 않는다

```bash
npx wrangler pages deployment list --project-name cham | head -6   # Source 열 = 커밋 해시
```

**커밋 해시가 보일 때까지 기다린다.** 응답으로 확인하려면 *새 코드에만 있는 신호*를
고른다 — 옛 코드에서도 참인 신호는 배포 여부를 가르지 못한다.
`curl` 로 `.html` 을 볼 때는 `-L` 을 붙인다(308).

## 검증

```bash
(cd public && python3 -m http.server 8777 --bind 127.0.0.1)
./venv/bin/python <script>.py            # Playwright
```

- **390px · 1280px** 두 폭 / 가로 스크롤 0건 / 콘솔 오류 0건
- 화면을 바꿨으면 **숫자만 보지 말고 스크린샷을 눈으로 본다** — 수치가 다 정상인데
  화면이 통째로 비어 있던 적이 있다
- 서버 동작은 **운영에서** 다시 본다. workerd 는 Workers 의 제한을 강제하지 않는다
- 자세한 함정은 `.claude/skills/verify/SKILL.md`

## 검증하며 만든 자료는 지운다

시험 주문은 매출로, 시험 가입은 회원 수로, 빈도 제한 카운터는 **다른 손님의 차단**으로
남는다. 무엇을 만들었는지 세어 두었다가 **그만큼 지우고, 지운 것을 보고에 적는다.**

## 깨졌을 때 — 스스로 고친다

배포 뒤 검증이 실패하면 되돌리지 말고 **원인을 찾아 고치고 다시 배포한다.**
`superpowers:systematic-debugging` 을 쓴다. 증상을 패치하지 않는다(절대규칙 5).

같은 항목에서 **세 번 연속 실패하면 멈추고 보고한다.** 네 번째 시도는
같은 자리를 다시 파는 것이지 진전이 아니다. 그때는 무엇을 시도했고 각각 왜 실패했는지,
그리고 선택지를 적는다.

**되돌려야 하는 경우**(운영이 실제로 망가졌을 때)는 즉시 `git revert` 하고
`docs/deploy.md` 의 복구 절차를 따른 뒤 보고한다. 망가진 채로 다음 항목에 가지 않는다.

## 목록이 비면

'대기'가 비면 **끝났다고 보고하고 멈춘다.** 할 일을 새로 지어내지 않는다.
남은 보류(B\*) 항목을 **운영자가 할 일 목록**으로 정리해 함께 낸다.

## 보고 형식

항목마다 짧게:

```
[항목번호] 무엇을 — 한 줄
  고친 파일 · 이유
  검증: 무엇을 어떻게 봤는가 (실측값)
  배포: 커밋 해시 · 운영 확인 결과
  정리: 검증하며 만들고 지운 자료
  (있으면) 기록한 실패
```

마지막에 전체 요약과 **남은 것**을 낸다. 하지 않은 것을 했다고 적지 않는다(절대규칙 10).
