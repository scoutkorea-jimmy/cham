# 개인정보 처리 기록

**무엇을 · 왜 · 어디에 · 얼마나 갖고 있는지**를 한 장에 적어 둔 내부 문서다.
공개하는 문서가 아니다 — 손님에게 보이는 것은 [개인정보처리방침](../public/privacy.html)이고,
이것은 그 방침이 **사실인지 대조하는 원본**이다.

- 근거: 「개인정보 보호법」 제30조(처리방침 수립·공개) · GDPR 제30조(처리활동 기록)
- 마지막 확인: **2026-08-15**
- 이 문서와 실제 코드가 어긋나면 **코드가 아니라 이 문서를 의심하기 전에 둘 다 본다.**
  방침에 적은 것과 실제가 다르면 그것이 가장 큰 문제다.

> **왜 이 문서가 따로 필요한가.** 방침은 손님에게 하는 약속이고, 이 문서는 우리가
> 실제로 무엇을 하고 있는지의 목록이다. 둘을 한 문서로 합치면, 기능을 하나 붙일 때마다
> 손님용 문장을 고치는 일이 되어 결국 아무도 갱신하지 않는다.

## 6. 안전하게 지키려고 하는 것

| 조치 | 어디에 |
|---|---|
| 비밀번호 PBKDF2-SHA256 해시 | `functions/_shared/auth.js` |
| 세션은 서버가 서명한 값(HMAC)으로만 확인 · 회원/관리자 자격이 서로 통용되지 않음 | 같은 파일 |
| 쿠키 HttpOnly · Secure · SameSite=Lax | 같은 파일 |
| 로그인 실패 시 IP 단위 지수 백오프 | `_shared/throttle.js` |
| 가입·주문·문의 빈도 제한 | 같은 파일 |
| 권한 10종 · 그룹별 접근 통제 | `_shared/perm.js` · `db/0004_roles.sql` |
| 관리자 화면·API 는 세션 없이 열리지 않음 (401 · 302) | `functions/_middleware.js` |
| 관리자 영역 색인·수집 거부 (`X-Robots-Tag`) | 같은 파일 |
| R2 의 `backups/` 는 밖에서 닿지 않음 — 이미지 함수가 `images` 표에 있는 id 만 내준다 | `functions/api/images/[id].js` |
| 매일 D1 덤프를 R2 에 보관 | `.github/workflows/backup.yml` |

**하지 않는 것**(과장하지 않기 위해 적는다): 저장 시 암호화(D1 이 제공하는 것 외에 따로 하지 않는다) ·
접속기록 별도 보관 및 정기 점검 · 침입탐지 · 망분리.

## 8. 사고가 났을 때

1. **막는다** — 관리자 비밀번호를 바꾸고(`관리자 > 비밀번호 변경`) 세션을 끊는다.
   회원 쪽이면 `members.token_min_iat` 를 올려 발급된 토큰을 모두 무효로 만든다.
2. **범위를 잰다** — 어느 표의 몇 건이 나갔는지. R2 `backups/` 의 직전 덤프와 대조한다.
3. **알린다** — 「개인정보 보호법」 제34조: 정보주체에게 **지체 없이**, 1천명 이상이면
   보호위원회·KISA 에 **72시간 이내** 신고. (GDPR 을 적용받는 경우에도 72시간이다.)
4. **적는다** — 경위와 조치를 [failures.md](failures.md) 에 다섯 칸으로 남긴다.

## 이 문서를 갱신해야 하는 때

- 받는 항목이 늘거나 줄 때 (양식에 칸 하나를 더하는 것도 해당한다)
- 새 외부 서비스를 붙일 때 (메일 발송·결제·분석 도구 — **전부 §5 에 줄이 하나 는다**)
- 보관 기간을 바꿀 때
- 약관·개인정보처리방침을 새로 시행할 때 (`_shared/consent.js` 의 `CONSENT_DOC_VERSION` 도 함께)

**갱신하면 방침(`public/privacy.html`)과 대조해 어긋난 곳이 없는지 본다.**
방침에 적힌 것이 실제와 다르면, 그것 자체가 위반이다.
