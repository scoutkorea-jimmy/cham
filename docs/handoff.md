# 인수인계 — 요청 추적

**이 문서가 원본이다.** 요청은 받는 즉시 여기에 적고, 끝나면 상태를 바꾼다.
대화는 흘러가지만 이 파일은 남는다 — 놓친 것이 있는지 확인할 때 여기부터 본다.

- 상태: `대기` 아직 시작 안 함 / `진행` 작업 중 / `완료` 배포·검증 끝 / `보류` 사용자 답변·값을 기다림
- 완료 조건: **운영 사이트에 배포되고, 실제로 동작하는 것을 확인**했을 때. 코드를 쓴 것만으로는 완료가 아니다.

현재 운영: **https://charmjt.org** (www 포함) · `main` push 시 자동 배포
Pages 기본 주소 https://cham-3ef.pages.dev 도 계속 응답한다 — 커스텀 도메인의 CNAME 대상이 이 주소다
(`cham.pages.dev` 가 아니다. 프로젝트 이름이 이미 쓰이고 있어 `-3ef` 가 붙었다)
관련 문서: [deploy.md](deploy.md) 배포·복구 · [migration-cloudflare.md](migration-cloudflare.md) 이전 계획

## 진행 — 작업 중

### S1 · 추석 시즌 한국어 검색 최적화 (2026-08-23 착수)

**요청**: "추석시즌이라 검색어 전쟁이 시작된다 — 한국어 기준으로 구글·네이버에서 잘 검색되게."

**조사에서 나온 것 — 사이트맵이 색인해 달라고 낸 주소가 빈 페이지였다.**
`sitemap.xml` 은 상품 상세 14건(`/product?id=`)을 싣는데, 크롤러가 실제로 받는 HTML 은
**본문 21자 · 제목은 14건 전부 "제품 상세"** 로 같다. `shop.js` 가 제목·설명·Product
구조화 데이터를 넣기는 하지만 **그것은 자바스크립트가 도는 뒤의 일**이라 크롤러는 못 본다.
구글은 이런 묶음을 중복·빈 문서로 보고 통째로 색인에서 뺀다 — 추석 주력인
`명절 장(醬) 3종 세트`·`서연 수제식초 선물상자`가 검색에 잡힐 수 없었다.
소식마당은 2026-08-22 에 같은 문제를 서버 렌더로 이미 풀었다(`_shared/post-seo.js`).
**상품에는 그 처리가 없었다.**

| 할 일 | 상태 |
|---|---|
| ① 상품 상세를 서버가 렌더 — 제목·설명·og·본문 + `Product`/`Offer` 구조화 데이터 | 완료 |
| ② JSON-LD 의 상대 주소를 절대 주소로 (`"item":"index.html"` 은 구글이 버린다) | 완료 |
| ③ 명절·추석 검색어를 메타에 반영 (상품엔 명절 세트가 있는데 메타엔 그 말이 없다) | 완료 |
| ④ 소식 글 `Article` + **네이버 서치어드바이저용 RSS** (`/rss.xml`) | 완료 |
| ⑤ `Course`·`ItemList`·영업정보 구조화 데이터 | 완료 |
| ⑥ 제품 목록·소식 목록도 서버가 싣는다 (조사 중 같은 병을 더 찾았다) | 완료 |

**검증**(`wrangler pages dev` · 실제 workerd + 로컬 D1):

| 화면 | 크롤러가 받던 본문 | 지금 |

| `/products` | 1,269자 · **상품 이름 0개** | 2,241자 · 14개 이름·가격·요약 + `ItemList` |
| `/news` | 187자 · **글 제목 0개** | 글 목록(제목·날짜·링크) |

브라우저 검증 390 · 1280px: SSR 잔류 0 · 가로 스크롤 0 · 넘침 0 · 콘솔 오류 0 (10개 조합).

**배포 뒤 운영에서 확인**(2026-08-23, 커밋 `830213f`): 상품 13건 전부 제각기 다른 제목과
본문(380~733자) · `Product` 구조화 데이터 · `/rss.xml` 200 · 조합 정보(전화 `+82-2-855-8806`,

### 발주처 확인이 필요한 표기 — HTML 주석에 있던 것을 옮겨 적는다

손님에게 나가는 HTML 에 내부 메모를 남겨 두면 소스를 보는 사람이 그대로 읽는다.

| 무엇 | 우리가 내린 판단 | 확인할 것 |

| 자격 명칭 | 전 페이지를 **'전통발효식품 체험지도사'** 로 통일 | 발주처 원문의 '체험지도자사' 는 오기로 보았다. 민간자격 등록 명칭이 무엇인지 |
| 과정 강수 | 일정표(12강) 기준으로 **'4단계' 골격**으로 구성 | 발주처 원문은 '4강' 이었다 |
| 연 1만 원 회원모집 | **안내 문구로만** 구현(가입·결제 없음) | 실제로 회비를 받을 것인지. 받는다면 결제 수단과 회원 등급이 따라온다 |

받은 것: 상표등록증 그림 한 장(제 40-2572359 호 · 2026.07.22 등록 · 제30류 와인식초 등 10건).

| 정한 것 | 이유 |
|---|---|
| **소개 페이지는 그림, 식초 페이지는 글자만** | 사용자 결정. 등록증을 두 곳에 두면 어느 쪽이 본디 자리인지 흐려진다. 식초 페이지에서는 한 줄로 알리고 소개 페이지로 보낸다 |
| 등록 사항 목록에 **상표등록** 행을 넣었다 | 사업자등록·통신판매업과 같은 성격인데 빠져 있었다 |
| 값은 **설정 `trademark`** 하나 | 두 페이지가 같은 값을 본다. 관리자 > 운영 설정 > 사업자 정보에서 고친다 |
| 확대는 **`data-modal="doc"`** 한 길 | 나중에 다른 증서가 붙어도 `data-src`·`data-caption` 만 주면 된다. 문서마다 코드를 새로 쓰지 않는다 |
| 그림은 폭 **1200px · 312KB** 로 줄여 넣었다 | 원본은 1700×2340. 모달에서 등록번호·발급기관이 읽히는 최소 크기다. `loading="lazy"` 라 페이지 아래까지 내려오기 전에는 받지 않는다 |
| 카드는 **좌 3 : 우 7 가로 배치**, 좁은 화면에서도 접지 않는다 | 처음에는 210px 고정에 700px 아래에서 세로로 접었는데 증서가 너무 컸다(사용자 지적). 3:7 로 바꾸고 접기를 없앴다 — 접으면 축소본이 화면 폭을 다 먹어 문서가 본문 행세를 한다. **다만 390px 에서 증서가 89px 이라 그림만으로는 알아볼 수 없다**(‘크게 보기’ 로 연다) |

**안내 문구를 함께 고쳤다.** 그 자리에 *"등록증·신고증 원본은 개인정보(생년월일 등)가
포함되어 있어 게재하지 않습니다"* 가 있었다. 바로 위에 등록증을 붙이면 앞뒤가 맞지 않는다 →
**"사업자등록증·통신판매업 신고증 원본은…"** 으로 대상을 좁혔다.
상표등록증은 법인등록번호가 `250151-*******` 로 가려져 있고 개인 생년월일이 없다 —
그래서 게재할 수 있는 문서다. 개인정보 처리 기록은 손댈 것이 없다(받는 칸이 늘지 않았다).

검증: 390 · 1280 두 폭에서 가로 넘침 0, 모달 열림·닫힘, 대화상자 안에 내용이 다 들어옴,
관리자 칸에 값을 넣으면 두 페이지에 반영되고 지우면 기본값으로 돌아옴.

작업 중 밟은 함정은 [failures.md](failures.md) 에 적었다(`height:auto` 누락).

### 소식마당 글 주소 · 사이트맵 (2026-08-15)

**글에 주소가 없었다.** `openPost(id)` 가 모달로 펼칠 뿐이라 셋을 못 했다 —
검색 노출 · 링크 공유 · 카톡 미리보기. 2026-07-31 에 강사에게 글쓰기를 열었으니
앞으로 쌓일 교육 소식이 전부 검색 밖에 남을 참이었다.

| 정한 것 | 이유 |
|---|---|
| 주소는 `/news?id=` | `/product?id=` 와 같은 꼴이고, `seo.js` 가 이미 `?id=` 를 canonical 에 남긴다. 안 남기면 글 스무 개가 `/news` 한 문서로 합쳐진다 |
| **서버가 본문을 HTML 에 넣는다** | 주소만 붙여서는 소용없다 — **크롤러는 자바스크립트를 돌리지 않는다.** `#post-ssr` 자리에 넣고, 화면이 뜨면 `board.js` 가 걷어낸다 |
| 걷어내는 이유 | 두 곳에 같은 글이 보이면 어느 것이 진짜인지 알 수 없다 |
| 닫힘은 **신호 하나**로 (`site:modal-closed`) | 모달 닫는 길이 셋(✕·바깥 클릭·닫기 버튼)이라 자리마다 붙이면 하나를 빠뜨린다 |
| `p.html` 은 이스케이프하지 않는다 | 에디터로 쓴 HTML 이라 이스케이프하면 태그가 글자로 보인다. 제목·글쓴이 같은 **평문만** 이스케이프한다 |

**운영에서 확인한 것** (시험 글을 하나 넣어 보고 **지웠다** — 흔적 0건):
크롤러가 보는 `<title>`·`description`·`og:title`·canonical 이 모두 그 글의 것 ·
본문이 HTML 에 실림 · sitemap 에 실림 · 목록에서 누르면 주소가 바뀜 ·
닫으면 `/news` 로 돌아옴 · 뒤로가기로 다시 열림 · 직접 들어오면 모달이 열리고
서버 본문은 0자로 걷힘 · 지워진 id 로 들어가도 목록이 그대로 200

**사이트맵**: `sitemap.xml` 은 원래 있었다(함수). 여기에 **글 주소와 `lastmod`** 를 더했다.
`lastmod` 는 `YYYY-MM-DD` 여야 하고 형식이 틀리면 검색엔진이 그 줄을 통째로 버린다.
사람이 보는 **`sitemap.html`** 을 새로 만들고 푸터에 링크했다(22개 링크, 끊김 0).

### 동의 이력 · 내 자료 내려받기 · 빈도 제한 (2026-08-15)

**빈도 제한(T9)** — `/api/submit` 15건/일 · 회원가입 5건/일. 넘기면 30초 → 1분 → 2분으로
늘어난다. 이미 있는 `_shared/throttle.js` 를 썼다. 로그인은 *틀렸을 때만* 세고 여기는
*성공·실패를 가리지 않고* 세므로 `count()` 라는 이름을 따로 뒀다 — 성공한 주문에
`fail()` 이라 적혀 있으면 읽는 사람이 멈칫한다. 한도를 넉넉히 잡은 이유는 **한 IP 를
여럿이 나눠 쓰기** 때문이다(통신사 NAT·사무실·교육장).
운영 실측: 1~15 통과, 16번째 429 `Retry-After: 29`. 가입은 7번째에서 429.

**동의 이력(T10)** — `consent_log` 표를 새로 뒀다. 지금까지는 동의를 **확인만 하고 버려서**
"언제 · 어느 판 약관에 동의했는가"를 댈 수 없었다. 입증 책임은 사업자에게 있다.

| 정한 것 | 이유 |
|---|---|
| **비회원도 남긴다** | 주문·신청·문의도 개인정보를 받는다. 회원만 남기면 실제 수집의 절반이 기록 밖이다. `ref_kind`·`ref_id` 로 그 건에 묶는다 |
| **IP 는 저장하지 않는다** | 입증에는 '언제·무엇에·어느 판'이면 충분하고 IP 자체가 또 하나의 개인정보다. 방침에 "접속 일시와 집계값만"이라 적어 두었으므로 IP 를 쌓으면 방침이 사실과 어긋난다 |
| 판(版)은 `CONSENT_DOC_VERSION` **한 곳** | 약관을 새로 시행하면 여기도 올린다. 안 올리면 새 판 동의가 옛 판으로 기록돼, 기록이 있는데 증명이 안 되는 상태가 된다 |
| 마케팅은 **켠 것도 끈 것도** | 지금 값만 있으면 "동의한 적 없다"에도 "분명히 껐다"에도 댈 것이 없다. 안 바뀌었으면 적지 않는다 |
| 옛 화면은 **아무것도 적지 않는다** | 무엇에 동의했는지 서버가 모르는데 '동의함'으로 적으면 기록이 거짓이 된다 |

여기서 곁다리로 잡은 것 둘:
- `member.js` 가 `agreeTerms: true` 를 **상수로** 보내고 있었다. 화면이 이미 막고 있어
  통과에는 지장이 없었지만, **서버가 남기는 기록이 화면이 아니라 상수를 적게 된다.**
  증명하려고 남기는 기록이 늘 참이면 아무것도 증명하지 못한다.
- 주문·문의의 동의 체크박스에 `name` 이 없어 **서버가 동의 여부를 아예 못 봤다.**
  화면만 막고 있었다 — 창구를 직접 부르면 동의 없이 접수됐다. 이제 서버가 확인한다.

**내 자료 내려받기(T11)** — `GET /api/members/export`. 마이페이지에 버튼과 동의 내역을 뒀다.
비회원 주문·교육신청·문의는 **담지 않고, 담지 않았다는 사실을 파일 안에 적는다** —
연락처로 끌어오면 가족이 번호를 함께 쓸 때 남의 자료가 섞인다. 빠진 줄 모르는 것이 더 나쁘다.

**관리자 회원 상세** — 그 사람의 주문 내역(`member_id` 로 묶인 것만) · 마지막 로그인 ·
동의 이력을 한 화면에 폈다. 지금까지는 주문 목록으로 가서 이름으로 다시 찾아야 했고,
동명이인이면 그것도 확실하지 않았다.

> **동의 이력은 2026-08-15 부터 쌓인다.** 그 전 가입·주문은 비어 있다 —

### 소식마당 글쓰기 권한 (2026-07-31)

지금까지 글쓰기는 **관리자 계정**만 할 수 있었다. 강사에게 교육 소식을 맡기려면
관리자 계정을 하나 더 내주는 수밖에 없었고, 그러면 주문·회원·설정까지 전부 열린다.

**관리자 > 회원 > (회원 선택) > 소식마당 글쓰기 권한**에서 게시판마다 켠다.

| 정한 것 | 이유 |
|---|---|
| 권한 회원은 **자기 글만** 고치고 지운다 | 권한을 준 사람이 늘어도 사고 범위가 자기 글로 한정된다. 그래서 `posts` 에 작성자를 남겼다(`author_kind`·`author_id`·`author_name`) |
| 작성자가 **빈 옛 글은 관리자만** | 이 열이 생기기 전 글은 전부 NULL 이다. 권한 회원에게는 남의 글로 다룬다 |
| 게시판 **단위로** 지정(공지·교육) | 게시판마다 열을 두지 않고 목록 한 칸(`members.post_boards`)에 담는다 — 게시판이 늘 때 스키마를 또 바꾸지 않는다 |
| **갤러리는 관리자만** | R2 저장공간을 쓰고 삭제가 되돌리기 어렵다 |
| **'중요' 표시는 관리자만** | 권한 회원이 세우면 공지 위에 자기 글을 올려 둘 수 있다 |
| 회원이 닿는 창구는 **한 건 단위**(`/api/posts`) | `PUT /api/admin/data/posts` 는 목록을 통째로 교체한다. 그 문을 열면 자기 글 하나를 올리려고 보낸 목록이 **남의 글을 전부 지울 수 있다.** 관리자 글쓰기도 같은 창구로 옮겨 규칙이 한 곳에만 있게 했다 |
| '내 글인가'는 **서버가 알려 준다**(`GET /api/posts` 의 `mine`) | 공개 목록에는 글쓴이 **이름만** 싣고 회원 id 는 싣지 않는다. 이름으로 맞추면 동명이인에서 남의 글에 수정 버튼이 뜬다 |

### 검증에서 잡아 고친 것
운영에 올려 실제로 눌러 보고서야 드러난 것들이다.

| 문제 | 원인 |
|---|---|
| 운영에서 로그인 전면 불가 | Workers 는 PBKDF2 를 **100,000회로 제한**. 210,000 을 넣었는데 **로컬 workerd 는 강제하지 않아** 개발 중엔 멀쩡했다 |

### 검증할 때 지킬 것

1. **배포 대기는 커밋 해시로 확인한다.** 최신 배포만 보면 *이전* 배포가 success 인 것을 보고 끝나 버린다 — 실제로 이것 때문에 CSS 가 안 올라간 것을 올라간 줄 알았다.
2. **숫자만 보지 말고 화면을 본다.** 섹션 수·앵커·넘침이 모두 정상인데 화면이 통째로 비어 있던 적이 있다.
3. **빈 DB 로 한 번 열어 본다.** 데이터가 있으면 `null` 기본값 문제가 드러나지 않는다.
4. **로컬에서 통과해도 운영에서 확인한다.** workerd 는 Workers 의 제한을 강제하지 않는다.
5. **검증하며 만든 데이터는 지운다.** 시험 주문이 매출로, 테스트 방문이 방문자 수로 잡힌다.
   (관리자 화면과 `login.html` 은 방문 집계에서 빠져 있다 — 관리자만 눌러 보는 검증은 안전하다.)
6. **AI 답은 시간만 재지 말고 내용을 읽는다.** 가장 빠른 모델이 가장 그럴듯하게 틀린 말을 했다.

## 구조 — 자료를 다루는 방식

### 읽기 — 최근 1년만 올린다
주문·신청·문의는 시간이 흐르며 계속 쌓인다. 전부 메모리에 올리면 관리자 화면이 뜨는
시간이 자료에 비례해 늘어난다. **기본은 최근 1년**(`?since=`), 그 이전은 부를 때만.

- 창 밖 건수를 세어 함께 준다 → 화면이 「지난 자료 N건 더 있습니다」로 알린다.
  **이 안내가 없으면 운영자는 자료가 사라진 줄 안다.**
- `created_at DESC` 인덱스가 이미 있어 창 조회는 인덱스를 탄다.
- 대상은 `orders` · `applications` · `inquiries`. 상품·교육과정은 '지금 쓰는 것'이라 제외.

### 쓰기 — 한 건만 보낸다
`PATCH` / `DELETE /api/admin/data/:kind/:id`. 목록 전체를 다시 보내지 않는다.

**이게 없으면 위가 사고가 된다** — 화면이 1년치만 들고 있는데 통째로 교체하면
그 이전 자료가 전부 지워진다. 안전장치를 두 겹으로 뒀다.

| 겹 | 무엇 |
|---|---|
| 1 | 한 건만 보낸다(주문 일괄 처리도 고른 건만) |
| 2 | 통째 교체가 남은 경로는 기간을 함께 보내 **지우는 범위를 창 안으로 묶는다** |

### 이 구조를 건드릴 때 반드시 확인할 것
`tools/data_window.py` 를 돌린다. **1년 이전 자료가 살아남는지**를 본다 —
목록을 통째로 저장하는 코드를 하나라도 되살리면 그 순간 지워진다.
`migrate()` · `dropDemoData()` 가 서버 모드에서 도는 것도 같은 사고 경로였다(둘 다 막아 뒀다).
