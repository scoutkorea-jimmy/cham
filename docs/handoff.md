# 인수인계 — 요청 추적

**이 문서가 원본이다.** 요청은 받는 즉시 여기에 적고, 끝나면 상태를 바꾼다.
대화는 흘러가지만 이 파일은 남는다 — 놓친 것이 있는지 확인할 때 여기부터 본다.

- 상태: `대기` 아직 시작 안 함 / `진행` 작업 중 / `완료` 배포·검증 끝 / `보류` 사용자 답변·값을 기다림
- 완료 조건: **운영 사이트에 배포되고, 실제로 동작하는 것을 확인**했을 때. 코드를 쓴 것만으로는 완료가 아니다.

현재 운영: https://cham-3ef.pages.dev · `main` push 시 자동 배포
관련 문서: [deploy.md](deploy.md) 배포·복구 · [migration-cloudflare.md](migration-cloudflare.md) 이전 계획

## 보류 — 사용자 결정·값이 필요

| # | 요청 | 막고 있는 것 |
|---|---|---|
| B1 | 관리자 비밀번호 교체 | **운영자가 직접** — 관리자 왼쪽 아래 `비밀번호 변경`. 그때까지 `admin`/`admin` 이고, 공개 저장소에 아이디와 해시가 있어 누구나 들어올 수 있다 |
| B2 | 실제 무통장입금 계좌번호 | **운영자가 직접** — 관리자 > 설정. 그때까지 예시값이라 손님이 엉뚱한 곳에 입금한다 |

| B4 | 도메인 연결 | 도메인 확정 시 다시 논의(사용자 요청으로 보류). `robots.txt`·`sitemap.xml` 은 손볼 것이 없고 `llms.txt` 한 줄만 |
| B5 | 회원 기능 범위 | **나중에 결정**(사용자). 당분간 관리자만 회원을 등록한다. 손님 직접 가입을 열면 공개 가입/로그인 화면·주문↔회원 연결·동의문 개정이 따라온다 |
| B6 | GitHub Pages 종료 | **도메인 연결할 때 함께**(사용자). 그때 로컬 어댑터·클라이언트 로그인 폴백·`public/` 분리를 한꺼번에 정리한다. 공개 저장소의 admin 해시도 그때 사라진다 |

### 검증에서 잡아 고친 것
운영에 올려 실제로 눌러 보고서야 드러난 것들이다.

| 문제 | 원인 |
|---|---|
| 운영에서 로그인 전면 불가 | Workers 는 PBKDF2 를 **100,000회로 제한**. 210,000 을 넣었는데 **로컬 workerd 는 강제하지 않아** 개발 중엔 멀쩡했다 |
| 관리자 화면이 통째로 빔 | 서버가 '한 번도 저장 안 함'을 `null` 로 답하는데 기본값을 주지 않아 `.length` 에서 죽었다 |
| 휴대폰에서 관리자 메뉴 접근 불가 | 사이드바를 화면 밖으로 밀면서 **불러올 버튼을 두지 않았다** |
| 설명서가 빈 화면 | `.reveal` 이 등장 대기로 남았다(관리자엔 그 관찰자가 없다) |
| 설명서 목차 사라짐 | 본문만 떼어 왔는데 목차가 그 밖에 있었다 |
| 단계 목록 글자가 한 자씩 끊김 | 문단이 둘 이상이면 세 번째 자식이 40px 번호 칸으로 밀렸다 |
| '맨 위로'가 챗봇 버튼을 덮음 | 같은 자리에 z-index 가 더 높았다 |
| 목차 카드 아이콘이 좌상단에 붙음 | `.toc span{display:block}` 이 `.icon-badge` 의 가운데 정렬을 덮었다 |
| 업로드 실패해도 "등록되었습니다" | `Promise.all` 결과를 보지 않고 성공 문구만 띄웠다 |
| 크기 제한 불일치 | 화면 10MB / 서버 8MB — 그 사이 파일이 조용히 실패했다 |
| 주문 검색 후 전체선택 | 화면에 없는 주문까지 선택돼 처리에 딸려 들어갔다 |
| 옵션 골라도 기본 용량이 남음 | 상품명을 브라우저가 만들었다 → 서버가 상품표에서 만들도록 |
| 좁은 화면 표가 37px 넘침 | 마지막 열(상태)이 화면 밖으로 밀렸다 |
| 대시보드 두 칸 사이 빈 배경 | `align-items:start` 로 짧은 쪽 아래가 비었다 |
| 챗봇이 17초씩 걸림 | 모델 목록 앞의 둘이 **폐기(5028)** 돼 매 질문마다 헛걸음한 뒤 16초짜리에 닿았다 |
| 빠른 모델이 없는 말을 지어냄 | 3b 는 0.9초지만 "입금 확인이 안 된 주문은 배송준비중이 됩니다"라고 답했다. **속도보다 정확도가 먼저** — 처음 쓰는 사람이 그대로 따라 하는 화면이다 |
| 답이 화면 밖으로 밀림 | 답에 설명서 본문이 딸려 와 길어졌는데 맨 아래로 내리고 있었다 — 답 대신 버튼이 보였다 |
| 배포 직후 검증이 옛 코드를 봄 | 배포 성공 뒤에도 잠깐은 이전 자산이 온다. **한 번 더 돌려 확인**한다 |
| 관리자 카드가 맞붙음 | 간격을 짝마다 따로 적어 와서 새 블록이 들어올 때 빠졌다. 대시보드 맨 위 두 패널이 간격 0 |
| 한 상자 안 좌우 기준선이 셋 | 제목 22 · 표 16 · 안내 23px. 눈이 기준선을 잃는다 |
| 모바일에서 여백이 안 줄어듦 | `28·32·64px` 을 인라인으로 박아 미디어쿼리를 이겼다. 토큰은 `clamp()` 라 390px에서 줄어야 한다 |
| `class` 가 한 태그에 두 번 | 뒤엣것을 브라우저가 무시해 스타일이 안 먹었다(치환 중 생김) |
| 없는 주소가 홈을 200 으로 돌려줌 | `404.html` 이 없었다. 오타·죽은 링크가 홈으로 보여 사용자는 틀린 줄 모르고, 검색엔진은 쓰레기 주소를 홈의 중복으로 색인한다 |
| 설명서가 로그인 없이 읽힘 | 화면만 관리자 전용이었고 **본문은 정적 파일**이었다 — 주소를 아는 사람은 `/assets/manual.html` 로 51KB 를 통째로 받았다 |

### 검증할 때 지킬 것

1. **배포 대기는 커밋 해시로 확인한다.** 최신 배포만 보면 *이전* 배포가 success 인 것을 보고 끝나 버린다 — 실제로 이것 때문에 CSS 가 안 올라간 것을 올라간 줄 알았다.
2. **숫자만 보지 말고 화면을 본다.** 섹션 수·앵커·넘침이 모두 정상인데 화면이 통째로 비어 있던 적이 있다.
3. **빈 DB 로 한 번 열어 본다.** 데이터가 있으면 `null` 기본값 문제가 드러나지 않는다.
4. **로컬에서 통과해도 운영에서 확인한다.** workerd 는 Workers 의 제한을 강제하지 않는다.
5. **검증하며 만든 데이터는 지운다.** 시험 주문이 매출로, 테스트 방문이 방문자 수로 잡힌다.
   (관리자 화면과 `login.html` 은 방문 집계에서 빠져 있다 — 관리자만 눌러 보는 검증은 안전하다.)
6. **AI 답은 시간만 재지 말고 내용을 읽는다.** 가장 빠른 모델이 가장 그럴듯하게 틀린 말을 했다.
